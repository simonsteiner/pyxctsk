A · The parser's adapters have no recognition question

Strong in-process live defect

src/pyxctsk/parser.py

What the module docstring promises

“Each adapter answers two questions independently: does the input look like my format, and can I parse it? This keeps every format's recognition and parsing logic in one place and makes each adapter testable in isolation.” — parser.py:12-16

Order stops being load-bearing. _unrecognized's three branches move into the adapters that own them.

Reproduced at this commit

$ echo -n '{"hello":"world"}' | pyxctsk convert
{"taskType":"CLASSIC","version":1,"turnpoints":[],"hello":"world"}
$ echo $?
0

$ echo -n '[]' | pyxctsk convert
Traceback (most recent call last):
  ...
TypeError: list indices must be integers or slices, not str

A ten-turnpoint .xctsk fed to _parse_qrcode_json reads as zero turnpoints with its whole content in unknown.

Problem

One adapter answers “yes” to input that is not its format, so tuple order is load-bearing and the error path re-derives four predicates the adapters should own.

Solution

Give the adapter the two-member interface its docstring describes: recognizes() beside parse().

Wins

  • locality: recognition beside parsing
  • leverage: a format is one row
  • the interface becomes the test surface
  • deletion test: _unrecognized concentrates

B · The QR shape is chosen twice, on two different inputs

Strong in-process live defect

src/pyxctsk/qrcode/task.py

Before — read decides on keys, write decides on the type

After — the shape is decided once and carried

Reproduced — and a second hole at the same seam

>>> q = QRCodeTask.from_dict({"g":{"d":"22:00:00Z","t":2}, "taskType":"W",
...     "t":[{"n":"A","z":"b`dpMgc{YgsB_X"}], "tc":None,"to":None,"version":2,"e":1})
>>> q.goal, q.earth_model
(QRCodeGoal(deadline=22:00:00, type=CYLINDER, ...), 1)
>>> q.to_dict()
{'T':'W','V':2,'t':[{'n':'A','z':'b`dpMgc{YgsB'}]}      # goal, e, tc, to, radius gone

>>> q2 = QRCodeTask.from_dict({"taskType":"CLASSIC","version":2,"t":[],
...     "g":"nonsense","s":123,"tc":None,"to":None})
>>> q2.goal, q2.sss, q2.unknown
(None, None, {})        # _A_DICT_OR_NOTHING says "it lands in unknown". It cannot.

Problem

Two shape decisions on two different inputs, and one lenient row that can put them into disagreement — plus a passthrough docstring asserting the opposite of the behaviour.

Solution

Decide the shape once when the payload is read; declare the third state a row can be in (declares a key, may decline to read it) so passthrough can carry the value.

Wins

  • locality: one decision, one place
  • a round-trip property test covers both
  • two docstrings become true

J · Two modules build the two earths

Worth exploring seam leak

Before — the choice made twice, in two formalisms

earth.py:5-7: “This module is where that choice is made, once.”

After — the earth owns both representations

Touches ADR 0003 — but fulfils it rather than contradicting it. The ADR's first decision is “One selector”; today that selector has two implementations, and only one of them refuses an unknown value. Not a reason to reopen the ADR.

Problem

Solution

  • the private import disappears
  • the raise-on-unknown guard covers projection

Top recommendation

start here A · Give the parser's adapters the recognition question their docstring promises

It is the only candidate with a demonstrated silent wrong answer at the library's front door, and it reproduces in one line:

$ echo -n '{"hello":"world"}' | pyxctsk convert
{"taskType":"CLASSIC","version":1,"turnpoints":[],"hello":"world"}

The interface it needs is already written down in parser.py:12-16; the implementation is four predicates that already exist, in a different form, inside _unrecognized. It removes the load-bearing tuple order, makes the four adapters testable in isolation as the docstring claims they already are, and turns an error path that re-derives four recognition rules into a question asked of the adapters that own them.

Runner-up

B — cheaper. Two holes at the model↔QR seam, both reproducible, both with a docstring asserting the opposite of the behaviour.

Cheapest wins

D is four accessors on a value that already exists; E is two deletions the package's own docstrings argue for.

Largest scope

C — the last hand-written field mirror. Start with the guard, not the table.
