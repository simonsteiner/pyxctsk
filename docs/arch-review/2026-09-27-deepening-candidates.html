Smaller, not carded

  • DistanceReport always optimizes the speed section, and the distance table throws it away: about 45 ms per drawing. It also reads the rows through 8 string keys (08-19 smaller finding 1, still open).
  • The crossing between the formats is too wide. QRCodeTask.from_task has 0 callers; from_task_waypoints, to_waypoints_json and to_waypoints_string are used only by tests; simplified= is never True.
  • distance.__all__ has 29 names, 11 of them used only by tests or scripts. VERSION and FULL_FORMAT_VERSION are the same value.
  • Stale docs: the Goal docstring points at pyxctsk.goal_line and the 2024 rule; plane.py:153; CLAUDE.md on where cylinders come from.
  • Task.to_json escapes non-ASCII and QRCodeTask.to_json doesn't.

Holding up well: the layering guard, the corpus, FormatAdapter recognition, OUTPUT_FORMATS, the validation rules, passthrough, the solver's interface, and task_viewer as a consumer.

Top recommendation

1 · Make the measured task's invariant hold, together with 3

The measured task is the module every S7F number flows through, and its one promise can be broken silently: 47.8 km reported where 94.0 km is true. Deepening its constructor is also the natural place to take the earth model off the turnpoints, because both changes land on the same seam and the same tests. Candidate 2 is the strongest defect on the input side and can be done independently.
